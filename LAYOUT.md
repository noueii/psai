# Layout: where things go

psai is meant to be forked. The **Owner** column says who owns each path:
- **you**: what you add in your fork. psai never ships these files, so pulling upstream updates doesn't conflict with them.
- **upstream**: what psai ships. Don't edit it in your fork.

`customize-harness` and `capture-knowledge` file everything by this table and write only to **you** paths. `scripts/check.sh` fails on any file under `workflows/ steps/ roles/ guides/ templates/ knowledge/ my-skills/` whose path doesn't match the **Goes in** column (`<x>` matches one path segment, `/**` anything below).

| You're adding | Goes in | Format | Owner |
|---|---|---|---|
| a workflow | `workflows/<name>.yaml` | state machine, see workflows/README.md | you |
| its simulator cases | `workflows/<name>.cases.yaml` | scripted outcomes and the expected path | you |
| a route to a workflow | `workflows/ROUTING.yaml` | a branch of the decision tree (created with the first workflow) | you |
| workflow diagrams | `workflows/GRAPHS.md` | generated by `scripts/graph.py --update-readme` | you |
| a step | `steps/<name>.md` | frontmatter `read:`, optional `skills:` + prose | you |
| a role | `roles/<name>.md` | frontmatter `may_change:`, `read:`, optional `skills:` + prose | you |
| your own reusable skill | `my-skills/<name>/SKILL.md` and its files `my-skills/<name>/**` | flat; `name` = folder; quoted `description` with "Use when ...". See my-skills/README.md | you |
| someone else's skill | `skills.yaml` | a pinned entry (name, source, path, ref) or an `ignore:` name. See my-skills/README.md | you |
| a skill for one repo only | `<repo>/.agents/skills/<name>/SKILL.md`, linked from `<repo>/.claude/skills/<name>` | same as my-skills; list it as optional | you |
| a role's knowledge | `knowledge/roles/<role>/INDEX.md` and `knowledge/roles/<role>/inbox.md` | index and inbox | you |
| a rule for one kind of work | `guides/<name>.md` | prescriptive prose, attached with `read:` | you |
| an output format | `templates/<name>.md` | the format, then a filled-in example | you |
| a rule for every task | `instructions/owner.md` | short bullets; injected live into every session | you |
| a finding during a task | `knowledge/inbox.md` or `knowledge/roles/<role>/inbox.md` | dated entry, see capture-knowledge | you |
| a promoted fact | `knowledge/facts/<topic>.md` | prose with sources | you |
| a promoted decision | `knowledge/decisions/<date>-<slug>.md` | Decision / Why / Source | you |
| the knowledge index | `knowledge/INDEX.md` | one line per file | you |
| an eval scenario for your workflow | `evals/scenarios/<name>.yaml` | see evals/README.md (don't reuse an upstream name) | you |
| the machinery | `skills/`, `plugins/`, `scripts/`, `migrations/`, `schemas/`, `install.sh`, `VERSION`, `evals/` (except your scenarios), `docs/`, `.claude-plugin/` | | upstream |
| the core instructions and this map | `instructions/global.md`, `LAYOUT.md`, every `README.md` | | upstream |

Folder READMEs (`<folder>/README.md`) describe each folder and are always allowed.

## The home (one machine; ADR 0011)
`~/.psai` (`$PSAI_HOME` moves it) is a folder that install.sh sets up:
- `framework/`: a link to the psai clone install.sh ran from;
- `overlay/`: your stack `nostack`, a git repo created on install. It holds `stack.yaml`, `stacks.yaml` (the installed stacks), and the paths marked **you** above: your own content, `instructions/owner.md`, `my-skills/`, `skills.yaml`, knowledge and every inbox;
- `stacks/<name>/`: each installed stack;
- `state/`: this machine's local state (`$PSAI_STATE` moves it): the session ledger, the stage worktree where changes wait for the retro's or sync's PR, retro reports, the install and migration records, the drift baseline, and `skills-cache/<stack>/` with the fetched `skills.yaml` entries. It is never shared.

A home that is still a link to a fork clone is converted on the next install (migration 0002): your files move into `overlay/`, `.state/` into `state/`, and the clone's own files are left alone.

Precedence, most specific wins: the step or role and its `read:` files > `instructions/owner.md` > `instructions/global.md`. psai has no per-repo layer: a rule for one repo goes in that repo's own AGENTS.md or docs (ADR 0011, Q2). Content is found by name with `psai resolve`, never by a hard-coded path.
