# Layout: where things go

psai is meant to be forked. The **Owner** column says who owns each path:
- **you**: what you add in your fork. psai never ships these files, so pulling upstream updates doesn't conflict with them.
- **upstream**: what psai ships. Don't edit it in your fork.

`customize-harness` and `capture-knowledge` file everything by this table and write only to **you** paths. `scripts/check.sh` fails on any file under `workflows/ steps/ roles/ guides/ templates/ knowledge/` whose path doesn't match the **Goes in** column (`<x>` matches one path segment).

| You're adding | Goes in | Format | Owner |
|---|---|---|---|
| a workflow | `workflows/<name>.yaml` | state machine, see workflows/README.md | you |
| its simulator cases | `workflows/<name>.cases.yaml` | scripted outcomes and the expected path | you |
| a route to a workflow | `workflows/ROUTING.yaml` | a branch of the decision tree (created with the first workflow) | you |
| workflow diagrams | `workflows/GRAPHS.md` | generated by `scripts/graph.py --update-readme` | you |
| a step | `steps/<name>.md` | frontmatter `read:` + prose | you |
| a role | `roles/<name>.md` | frontmatter `may_change:`, `read:` + prose | you |
| a role's knowledge | `knowledge/roles/<role>/INDEX.md` and `knowledge/roles/<role>/inbox.md` | index and inbox | you |
| a rule for one kind of work | `guides/<name>.md` | prescriptive prose, attached with `read:` | you |
| an output format | `templates/<name>.md` | the format, then a filled-in example | you |
| a rule for every task | `instructions/owner.md` | short bullets; injected live into every session | you |
| a finding during a task | `knowledge/inbox.md` or `knowledge/roles/<role>/inbox.md` | dated entry, see capture-knowledge | you |
| a promoted fact | `knowledge/facts/<topic>.md` | prose with sources | you |
| a promoted decision | `knowledge/decisions/<date>-<slug>.md` | Decision / Why / Source | you |
| the knowledge index | `knowledge/INDEX.md` | one line per file | you |
| an eval scenario for your workflow | `evals/scenarios/<name>.yaml` | see evals/README.md (don't reuse an upstream name) | you |
| a rule for one repo only | `<repo>/.harness/<same path as above>` | same format; created on first use; wins over the shared file | you |
| the machinery | `skills/`, `plugins/`, `scripts/`, `install.sh`, `evals/` (except your scenarios), `docs/`, `.claude-plugin/` | | upstream |
| the core instructions and this map | `instructions/global.md`, `LAYOUT.md`, every `README.md` | | upstream |

Folder READMEs (`<folder>/README.md`) describe each folder and are always allowed.

Precedence, most specific wins: `<repo>/.harness/` > the step or role and its `read:` files > `instructions/owner.md` > `instructions/global.md`.
