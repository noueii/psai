# 0009: Skills by name on roles and steps; my-skills/, pinned skills.yaml, a live registry (2026-11-21)
- Decision: roles and steps name the skills they need, `skills: {required, optional}`; the step's add to the role's. `work` runs `harness.py skills brief <role> <step>` and puts its line in the role agent's brief: each skill's "use when" and its SKILL.md path, since a plugin-namespaced or path-less skill name isn't invocable the same way in every tool. Exit 3 (a required skill is missing) means escalate from that node before starting the role, offering to install it; a missing optional skill goes in the final report. Roles may never list `request-router` or `work`.
- Where skills live (LAYOUT.md): your own in `my-skills/<name>/`; other people's as pinned `skills.yaml` entries (name, source, path, ref: a tag or commit, never a branch), fetched by install.sh into the git-ignored `.skills-cache/<name>/` and linked like psai's; one repo only in that repo's `.agents/skills/` with a `.claude/skills` link, listed as optional. `my-skills/` and `skills.yaml` are user-owned, so psai ships neither (only my-skills/README.md).
- The registry (`harness.py skills`, in `scripts/skills.py`) scans psai's folders, each tool's user skill folders (~/.claude/skills, ~/.agents/skills, opencode's, ~/.pi/agent/skills, ~/.omp/agent/skills) and the current project's, and maps each to the tools that read it. A skill in a user tool folder that isn't a link into the clone and isn't on `ignore:` is unmanaged: reported by check.sh and in the nudge as a count, never blocked. Duplicates (two real copies) and project-only required skills warn; a required skill that resolves nowhere fails.
- Adopt (`install.sh --adopt <name>`): a skill `npx skills` installed (`~/.agents/.skill-lock.json`) becomes a skills.yaml entry pinned to the source's current HEAD commit, and its old copy moves to `.skills-cache/.adopted/` (not into a tool folder, where tools would load it). Anything else is the user's own and moves into `my-skills/`; if it was only a link to a folder elsewhere, that folder is copied and left in place. skills.yaml is edited as text so comments survive.
- Why: roles need skills reliably and visibly, every tool must see the same set, and the owner's existing skills must keep working while psai takes over only what it's asked to.
- Source: PR #3 brief; `scripts/check.sh` (L0/L1 skills), evals `role-skill` and `missing-skill`.
- Note (2026-11-22, [0011](0011-framework-and-stacks.md) section 9.2): skills come from the framework, the overlay and each installed stack (its `my-skills/` and `skills.yaml`, cached per stack in `state/skills-cache/<stack>/`). The tools see one copy per name (psai's reserved, then the overlay's, then the higher-priority stack's); a role's brief resolves each name from its own stack. Adopt goes to the overlay (`psai adopt`), or `--to` a dev stack.
