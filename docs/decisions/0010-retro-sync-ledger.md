# 0010: Retro at task end, sync only where a workflow says, a local session ledger, migrations, one `psai` command (2026-11-21)
- Decision: nothing goes to GitHub while a task runs. `capture-knowledge` writes only to inboxes; `customize-harness` only stages (edits and validates in the stage worktree `.state/stage`, no branch, no PR).
- Decision: the `retro` skill runs at task end: `work` always runs it after a workflow (or at a `retro` node); outside workflows the agent runs it when a task is done and something was captured (one nudge line); and as a safety net, a session that ended with work but no retro is marked in the ledger and the next session's nudge asks for it. It reads the run (`psai retro gather`), ranks findings (Matt Pocock's retro categories plus workflow shape, roles missing skills, knowledge and drift), stages changes, and `psai retro finish` builds ONE branch with everything from the task (stage worktree + the live clone's uncommitted user-owned files), the report as its description, and pushes it to the fork. Nothing worth changing: no PR. Project findings go in the final report; it never edits other repos.
- Decision: `sync` is a skill run only where a workflow has a `sync` node, or when the owner asks. No startup check, no schedule. It runs a deterministic check first (fetch with a short timeout; installed commit vs HEAD; pending migrations; unsynced ledger sessions, staged changes or reports; tool drift by fingerprints of the tools' skill folders, global instruction files outside psai's lines and Claude's memory folders) and stops at zero cost when nothing is out of sync. Otherwise: fast-forward only (local inbox entries are kept by entry-union; anything else that conflicts changes nothing and reports "psai update waiting: needs you"), re-install, migrations, drift adoption by staging, and ONE PR per machine per run on `psai/sync-<host>-<date>`, built in a separate worktree. When a `sync` node follows the retro, the retro doesn't build its own branch: sync carries its report.
- Trade-off: psai updates only when a workflow runs sync or the owner asks an agent to sync.
- Decision: the session ledger is local (`.state/sessions/<id>.json`, git-ignored): id, tool, project, start/end, workflows, escalations, retro done or pending, captured counts, drift seen, psai version, synced branch. The plugins write it at session start and end (Claude Code SessionStart/SessionEnd hooks; pi and omp `session_start`/`session_shutdown`; opencode `session.created`/`session.deleted`); `trace.sh` adds workflows and escalations; retro and sync mark it.
- Decision: `migrations/NNNN-<slug>.sh` run once per machine from install.sh, recorded in `.state/migrations.json`. 0001 removes the old `~/.harness` link.
- Decision: one `psai` command (`scripts/psai.py`, linked as `~/.local/bin/psai`) with install, update, status, doctor, sync, retro, adopt, skills, ledger, check, context, graph, simulate. The existing scripts stay as its implementations.
- Why: the owner wants every task to teach the harness, reviewed as one PR, without background jobs or surprise network calls.
- Source: PR #4 brief; `scripts/check.sh` (L0/L1 sync, ledger, migrations), evals `retro` and `retro-sync`.
