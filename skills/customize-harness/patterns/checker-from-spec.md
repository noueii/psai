# A checker that works from the spec

**What:** the role that writes tests and checks gets the spec and acceptance criteria, not the implementer's notes.
**Why:** checks derived from the implementation confirm what was built, not what was asked.
**How:** in the checker's role brief, say it works only from the spec. The workflow passes it the spec, and a clarify step writes one (with a template, e.g. `templates/spec.md` in the workflow's folder).
